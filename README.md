# Heritage Trails Planner

## PROJECT OVERVIEW

Build a full-stack web application called **"Heritage Maharashtra"** (working title) — an AI-powered Smart Heritage & Cultural Tourism platform. The MVP is scoped to **Maharashtra state**, but the architecture must be state-agnostic so it can be extended to other Indian states later (don't hardcode "Maharashtra" into core logic — treat it as a data/config layer).

**Core user flow:**

1. User lands on a homepage dominated by a large interactive map of Maharashtra with its districts.

2. Heritage/cultural sites appear as clickable pins/markers on the map (e.g., forts, temples, caves, museums, festivals, craft villages).

3. Clicking a pin opens a **card/modal** with that site's heritage & cultural details (history, images, timings, entry fee, best time to visit, accessibility, safety notes).

4. From that card, the user can click **"Add to Itinerary"**.

5. User proceeds to an **AI Itinerary Planner** page where they select interests/days/budget, and the selected site(s) get slotted into a day-wise itinerary generated by an LLM, with multilingual descriptions.

---

## TECH STACK

- **Frontend:** React (Vite) + Tailwind CSS

- **Map library:** Leaflet.js with react-leaflet, using a Maharashtra districts GeoJSON overlay (or Mapbox GL JS if you prefer a more polished/custom map style)

- **Backend:** Node.js + Express (or Python FastAPI if easier to wire up in Replit)

- **Database:** PostgreSQL via Supabase, or Replit DB / SQLite for MVP simplicity — store as structured relational data so it's easy to query by district/category

- **AI/LLM integration:** Anthropic Claude API (or OpenAI API) for:

  - Itinerary generation

  - Short AI-generated/curated "Story Mode" narration per site

  - Heritage chatbot/guide assistant

- **Auth (optional for MVP):** Simple email/password or skip auth entirely and use local/session storage for saved itineraries

- **Deployment:** Replit Deployments

## PAGE 1 — HOMEPAGE (Interactive Map)

- Full-viewport (or near-full) SVG/GeoJSON map of Maharashtra, divided by district, similar to a choropleth map — each district lightly color-coded or highlighted on hover.

- Overlay clickable **pin markers** at real lat/long coordinates of popular heritage sites (start with ~15-20 seeded sites across a few districts: e.g., Raigad Fort, Ajanta & Ellora Caves, Shaniwar Wada Pune, Gateway of India Mumbai, Chhatrapati Shivaji Terminus, Kolhapur Mahalaxmi Temple, Lonar Crater Lake, Sindhudurg Fort).

- Pins should use a distinct heritage-themed icon (e.g., small fort/monument icon), and clicking one:

  - Smoothly zooms/pans the map to that location, AND

  - Opens a **site detail card** (modal or slide-in side panel — your choice, but modal is simpler for MVP).

- A search bar above the map lets users search sites by name or filter by category (Forts, Temples, Caves, Museums, Festivals, Crafts).

- A category filter/legend lets users toggle pin visibility by type.

- Language toggle (English / Marathi / Hindi at minimum) in the top nav.

## PAGE COMPONENT — SITE DETAIL CARD

When a pin is clicked, show a card containing:

- Site name (in selected language)

- 1-2 images (placeholder images are fine for MVP, structure it so real images can be swapped in)

- Short history/heritage description (2-4 sentences)

- Cultural significance / legends section ("Story Mode" — can be AI-generated on demand via the LLM API, with a "Narrate this story" button that calls the AI and displays/optionally reads the text)

- Practical info: timings, entry fee, best time to visit, nearest transit

- **Accessibility & Safety layer:** wheelchair access (yes/no/partial), nearby medical facilities, safety advisories, emergency contact number for that district

- A **"Add to Itinerary"** button

- A **"Ask about this place"** button that opens the chatbot pre-loaded with context about this specific site

## PAGE 2 — AI ITINERARY PLANNER

- Shows all sites the user has added ("selected spots"), plus lets them add more via a searchable list or by returning to the map.

- Input form: number of days, budget range, interests (heritage/nature/food/adventure/shopping — multi-select), starting city/district, group type (solo/family/friends).

- On submit, call the LLM API with a structured prompt containing: selected sites, user inputs, and site metadata (location, category, typical visit duration) → LLM returns a **day-wise itinerary** as structured JSON (day number, ordered stops, suggested time slots, travel notes, short multilingual blurb per stop).

- Render this itinerary in a clean day-by-day timeline UI (Day 1, Day 2, etc., each with ordered stops and times).

- Allow the user to regenerate, edit day order (drag-and-drop optional stretch goal), or export/print the itinerary.

## PAGE 3 (STRETCH) — HERITAGE CHATBOT

- A floating chat widget available site-wide.

- Backend injects Maharashtra heritage context (and specific site context if launched from a site card) into the system prompt before calling the LLM.

- Handles queries like "best time to visit Ajanta Caves", "is Kolhapur safe for solo travelers", "local festivals happening this month".

## DESIGN DIRECTION

- Map should feel like the visual anchor of the entire site — large, central, immersive, not a small widget buried in a page.

- Use warm, earthy tones (terracotta, ochre, deep maroon, gold accents) to evoke heritage/culture rather than a generic "tech startup" blue palette.

- Cards/modals should use soft shadows, rounded corners, and real breathing room — avoid cramming all info into a tiny popup.

- Mobile responsive: on small screens, map should still be usable (pinch/zoom), and cards should become full-screen sheets rather than tiny modals.

- Don't hardcode API keys — use Replit Secrets for the LLM API key.

- Prioritize getting the map + pin + card flow rock solid before building the itinerary AI feature — that's the visual centerpiece and the differentiator judges/users will notice first.
